# Open Rails — Agent Guide

Open-source **Railroad Tycoon spiritual successor**: an open-ended sandbox
where you build railways, stations, and train routes in an 1850s American
valley and watch cargo — and money — move. No victory condition; the loop
itself is the game.

- **Runtime:** Godot **4.7.2 Standard**, GDScript only, **Compatibility**
  renderer, orthographic isometric camera (yaw 45°, pitch fixed 35.264°).
- **Assets:** Blender is an **offline asset compiler** — assets are
  `asset.py` + `asset.toml`, compiled headlessly to `.glb`. Blender never
  exists at runtime; `.blend` files are not source.
- **World:** one hand-authored 256×256 tile sandbox, *Founder's Valley*:
  2 towns, 2 coal mines, 2 power plants, water/forest/hills/plains.
- **Content scope:** 3 cargos (passengers, mail, coal), 2 industries,
  1 station class, 1 locomotive (4-4-0) + 3 wagons.

Authoritative spec: `docs/requirements/v1.md`. Active plans live in
`openspec/changes/*/` (proposal/design/spec/tasks) — each `design.md` records
the decisions this guide summarises.

## Commands — everything runs through `python tools/rr.py`

Agents use the same commands humans use. Never invoke Godot or Blender
directly; never add a second task runner. All commands exit 0 on success.

```bash
python tools/rr.py game run                  # launch the game
python tools/rr.py game run --godot-args "…" # forward extra args to Godot
python tools/rr.py test                      # headless simulation test suite
python tools/rr.py test --filter rail        # only test files matching "rail"
python tools/rr.py check                     # import all scripts + verify shared conventions
python tools/rr.py constants                 # regenerate world_constants.gd from world.toml
python tools/rr.py constants --diff          # report constant drift without writing
python tools/rr.py art list                  # discover assets in art/assets/
python tools/rr.py art build steam_440       # build one asset → game/generated/
python tools/rr.py art build --all --jobs 3  # parallel build (isolated Blender procs)
python tools/rr.py art build --all --force   # ignore the input-hash build cache
python tools/rr.py art validate --all        # check scale/materials/tris/animations
python tools/rr.py art preview steam_440     # 8 angles × 2 zooms → build/previews/
python tools/rr.py stress --ticks 2000       # synthetic stress world, headless
```

Run from the repository root. `python tools/rr.py --help` lists the surface.

### Toolchain discovery

Godot/Blender are located in this order: explicit `--godot` / `--blender`
flag → `RR_GODOT` / `RR_BLENDER` environment variables → `~/.rr/toolchain.json`
(`{"godot": "...", "blender": "..."}`) → conventional install paths
(`godot`, `godot4` on PATH, `/Applications/Godot.app/…`, `blender`,
`/Applications/Blender.app/…`). A missing toolchain fails with the searched
paths listed and a download hint for Godot 4.7.2-stable. (Note: the
`add-project-foundation` design doc mentions a repo-local pin file; the
shipped code reads `~/.rr/toolchain.json` — trust the code.)

The Godot binary is not installed by default; export `RR_GODOT` before
`game run` / `test` / `check` / `stress`.

## Hard performance rules (spec §112 — violations block review)

- **No node per terrain tile.** World state is typed arrays (`WorldGrid`,
  index `y*width+x`); a 256×256 map creates zero per-tile nodes.
- **No material per building.** One shared vertex-colour material everywhere;
  company colour via one parameterised material.
- **No physics body per rail tile** (or per anything static). Selection =
  camera ray → terrain heightfield → tile → `occupancy_id`.
- **No pathfinding per tick.** Rail paths are computed on route creation and
  `track_changed`; construction previews cache per `(start, goal, revision)`.
- **No full terrain rebuild for a local edit.** Dirty-region rebuilds; a tile
  edit touches ≤ 4 chunks (one-tile skirt). Rebuild counters are exposed.
- No animating offscreen decoration. Prefer chunking, `MultiMeshInstance3D`
  instancing, cached paths, event-driven updates.
- Budgets: 60 FPS @ 1080p on integrated graphics, RAM < 700 MB, GPU < 512 MB,
  LOD0 triangle caps per class — see
  `.agents/references/performance-budgets.md`. Press `F3` in-game.

## Invariants (checked by tests and `rr.py check`)

1. **All money flows through `EconomyService`.** No `cash -= cost` anywhere
   else; every mutation writes a ledger transaction, and a test guard asserts
   opening balance + Σ ledger == cash.
2. **Simulation never calls UI or presentation.** Domain services emit typed
   signals (`track_changed`, `station_created`, `train_created`,
   `train_arrived`, `cargo_delivered`, `money_changed`, `month_changed`);
   UI listens. The domain test suite must pass with no UI loaded.
3. **Stable 64-bit entity IDs** (`TownId`, `IndustryId`, `StationId`,
   `TrainId`) everywhere. Never persist or pass scene-node paths.
4. **`TILE_SIZE = 1.0` / `HEIGHT_STEP = 0.25` come from
   `art/config/world.toml` only.** Runtime reads the generated
   `game/src/domain/world/world_constants.gd`; drift fails `rr.py check`.
   Never hard-code scale in an asset script or gameplay module.
5. **Determinism:** fixed 20 Hz integer ticks, no wall-clock or unseeded
   `randf()` in simulation; identical starting state + ticks ⇒ identical
   result.
6. **Generated output is not source:** `game/generated/` and `build/` are
   git-ignored and rebuilt by the CLI.
7. **`game/data/` JSON is the only place definitions live;** new cargo,
   wagon or industry content must need no transport-system code change.

## Out of scope for V1 (spec §115 — do not build these)

Victory conditions, campaign, AI companies, multiplayer, stock market,
company acquisition, bonds, loans, shareholders; signals, train collision,
block reservation; bridges, tunnels; dynamic town growth, advanced industry
chains, season system, day/night cycle, weather; procedural map generator,
map editor; modding API, Steam Workshop, achievements, technology tree,
historical locomotive progression. The architecture must not *prevent* these,
but V1 code must not include them.

### Skill index (`.agents/skills/<name>/SKILL.md`)

**Art pipeline (Blender offline):** `blender-headless` (invocation, jobs,
logs) · `art-style` (shape language) · `asset-scale` (canonical dimensions) ·
`voxel-modeling` (geometry techniques) · `material-palette` (shared materials)
· `animation-authoring` (mechanical animation, states) · `gltf-export` (GLB
contract) · `mesh-optimization` (budgets, cleanup) · `lod-policy` (LOD0/1/2) ·
`asset-validation` (automated checks).

**Runtime:** `godot-project` (project layout/conventions) ·
`camera-navigation` (the only camera system) · `runtime-rendering` (chunks,
instancing, draw calls) · `runtime-effects` (pooled smoke/steam) ·
`iso-world` (tile↔world conversion, selection) · `terrain-system` (grid +
chunked terrain).

**Gameplay (domain):** `rail-network` (bitmask graph) · `rail-builder` (plan/
preview/commit/undo) · `station-system` (placement, catchment, inventory) ·
`train-system` (consists, movement) · `route-system` (stops, recalculation) ·
`cargo-system` (batches, load/unload) · `industry-system` (producers/sinks) ·
`town-system` (cargo sources) · `economy` (EconomyService, ledger) ·
`simulation-clock` (ticks, calendar) · `save-load` (versioned JSON, atomic).

**UX:** `ux-principles` (interaction law) · `ui-components` (themed widgets) ·
`build-mode-ux` (tools, ghosts, previews) · `input-navigation` (keybindings,
focus/follow).

**Cross-cutting:** `data-contracts` (JSON schemas in `game/data/`) ·
`testing` (headless suite, determinism) · `performance` (measurement) ·
`diagnostics` (`F3` overlay, stress world, counters).
